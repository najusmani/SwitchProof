1.4.5

1 October 2026Your own types, sources and currencies

Your own transaction types Team

  • Design a transaction type from a built-in one: its own name, message class (x100, x120, x200, x220), processing code and fields. Add, change or leave out any field; values can use placeholders such as {random:8}, {date:MMdd}, {account} and {amount}.
  • A live preview shows the exact message for the active switch, field by field, and flags values that don't fit the field. Test send one message before you save.
  • Saved types work straight away in load tests, bundles and UAT cases. Money moves as in the type they started from, so reversals, settlements and money checks work the same.
  • Submit a type for approval to have it shipped as a built-in type for everyone. Only its structure is sent; fixed values are masked unless you choose to share them.

Sources: where a transaction comes from

  • Ready-made sources per switch: on-us, remote on-us, off-us, international and our card abroad. Each sets the card (F2), acquirer (F32) and, if needed, forwarding institution, terminal, merchant type (F18) and entry mode (F22).
  • Pick a source for a run, for each bundle row or for each UAT step. Results and reports are grouped by source.
  • The money check compares the switch's on-us / off-us decision with the source, so a card or BIN set up wrongly on the switch is caught.

Currencies

  • Settlement amount and currency with their rate (F5, F50, F9) and cardholder billing amount and currency with their rate (F6, F51, F10), set per source.
  • The money check understands converted postings: it shows the rate the core used, compares the debit with the billed amount, and flags a posting that wasn't converted at all.

1.4.3

27 September 2026Stand-in simulation

Core banking cutover rehearsal Enterprise

  • Eight steps, each a button as on the night: switch to stand-in, positive balance file, transactions at the switch, connect the new core, samples, release the queue, reconcile, fully online.
  • The simulated switch approves or declines in stand-in on its own rules and the positive balance file (51 not enough balance, 61 over a stand-in limit, 91 no balance record), and queues what it approved.
  • The queue is released as advices (0220, 0120, 0420) with the repeats a switch sends when it gets no answer (0221, 0121, 0421), in time order and without overtaking.
  • Transactions that began in the legacy core: reversals of withdrawals approved just before the cut-off, and completions of holds the migration brought over. A force-post test sends a withdrawal above the balance.
  • Reconciliation of every RRN (posted once, reversals, holds, value dates), of each account (balance before plus what the switch approved equals balance after) and of the switch's totals against the GLs.
  • Replays of up to 30,000 advices, several in flight, with a "must finish within" target and a live projection. Printable report and CSV.
